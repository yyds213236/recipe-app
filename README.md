# 小锅菜谱 · 今天吃点什么

一个纯前端、零构建、完全离线的中文家常菜 Web App。双击 `index.html` 就能用，不联网、不装依赖、不加载任何 CDN 资源。

- 手机优先（按 390×844 设计），桌面自动适配到 4 列
- 底部三个 Tab：**菜谱 / 食材 / 我的菜篮**
- 核心玩法：勾选冰箱里现有的食材 → 算出「现在就能做 / 差 1 样 / 差 2 样以上」

---

## 一、怎么跑

```bash
# 方式 A：直接双击
open /Users/apple/Desktop/recipe-app/index.html

# 方式 B：起个静态服务器（可选，行为一致）
cd /Users/apple/Desktop/recipe-app && python3 -m http.server 8000
```

数据内联在 `data.js`（`window.RECIPE_DB = {...}`）里，用普通 `<script>` 引入，所以 `file://` 下没有 fetch、没有 CORS 问题，首屏无网络请求。

> 建议用 Chrome / Edge / Safari 最新版。`file://` 下的 `localStorage`（菜篮、已选食材、API Key）在 Chrome、Safari 都可用；个别「禁止本地存储」的浏览器隐私模式下会退化为不持久（功能仍可用，刷新后丢失）。

## 三、数据结构

```js
window.RECIPE_DB = {
  categories: ["蔬菜","肉禽","水产","蛋奶","豆制品","主食","调料","干货/菌菇"],
  tags:       ["快手","下饭","素菜","宴客","汤","早餐"],
  ingredients: [ /* 见下 */ ],
  recipes:     [ /* 见下 */ ]
};
```

### 食材

```js
{ id: "tomato", name: "番茄", alias: ["西红柿","洋柿子"], category: "蔬菜", unit: "个", emoji: "🍅" }
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 唯一英文别名式主键，菜谱只引用它 |
| `name` | string | 主名称 |
| `alias` | string[] | 常见叫法，搜索时一并匹配（316 种全部有别名，共 465 条） |
| `category` | string | 8 类之一，决定食材页分组与采购清单顺序 |
| `unit` | string | 默认计量单位（个/克/根/勺…） |
| `emoji` | string | 图标，离线可用 |

### 菜谱

```js
{
  id: "tomato-egg", name: "番茄炒蛋", emoji: "🍅", cuisine: "家常",
  tags: ["快手","下饭","素菜"],
  time: 10, difficulty: 1, servings: 2,
  ingredients: [
    { id: "tomato", amount: 2, unit: "个", optional: false },
    { id: "salt",   amount: 2, unit: "克", optional: false }
  ],
  steps: ["番茄去蒂切滚刀块，鸡蛋加一小撮盐打散，打到表面起细泡。", "…"]
}
```

- `difficulty`：1 简单 / 2 中等 / 3 有点难
- `optional`：可选配料（如点缀用香菜），**不参与「缺几样」计算**
- `steps`：4–6 步，每步 15–35 个汉字，带火候与判断标准（「油温六成热」「边缘凝固」）

## 五、多选反查算法

```txt
缺的食材(r) = { g ∈ r.ingredients | !g.optional
                             ∧ (开关打开 ∨ g.category ≠ "调料")
                             ∧ g.id ∉ 已选食材 }
档位      = 缺 0 → 现在就能做 ; 缺 1 → 差 1 样 ; 缺 ≥2 → 差 2 样以上
排序      = 缺的样数升序 → 烹饪时间升序（like-for-like 时先推快手菜）
```

要点：

1. **调料默认不计入缺失**（盐、生抽、油这类几乎家家都有），结果页有开关「把调料也算上」，打开后按 `category === "调料"` 一并计入，并写入 `localStorage` 记忆。
2. **可选配料永不计入**（`optional: true`），避免「差一样香菜」这种事把菜踢出「现在就能做」。
3. 缺的食材在卡片里用红色 chip 逐样列出（超过 8 样折叠为 `+N`）。
4. 顶部统计「已选 N 种食材，可做 M 道菜」，并给出「另有 X 道只差 1 样 · Y 道差 2 样以上」。
5. 食材页已选 0 时结果页给引导；若一道「现在就能做」都没有，会在列表上方给软提示「再多选两样，能解锁更多菜」并点名最接近的那道菜，**不会**把列表替换掉。

## 六、功能一览

**菜谱页**
- 搜索菜名或食材名，**支持别名**（输入「西红柿」能搜到番茄炒蛋等 10 道菜）
- 分类 chip：全部 / 快手 / 素菜 / 汤 / 下饭 / 宴客 / 早餐
- 卡片：emoji + 菜名 + 时间 + 难度（按难度着色的文字）+ 食材数；已选食材时右上角显示「可做 / 缺 N」

**菜谱详情（底部推起的 sheet）**
- 头部：emoji、菜名、时间/难度/份量/菜系
- 食材清单可逐项勾选，调料单独一组；顶部显示 `已完成/总数`
- 步骤卡片：点「标记完成」变灰置顶序号变 ✓；「下一步 →」自动推进并滚动到当前步
- 右上角 ⏱ 计时器：1 / 3 / 5 / 10 / 15 分钟预设，开始/暂停/重置，到点用 **WebAudio 合成**三声蜂鸣（880 Hz → 1180 Hz），不依赖任何音频文件
- 底部「加入我的菜篮 / 已在菜篮 · 移出」

**食材页**
- 分类 tab + 搜索；食材以 chip 网格排列，点一下选中（橙棕填充 + 右上角 ✓）
- 顶部固定「已选 N 种」横条，可展开看全部、单个删除、一键清空
- 底部常驻「看看能做什么（N）」

**我的菜篮**
- 收藏列表（`localStorage` 持久化），可移除
- 「合并食材清单」：同名合并、**只在单位相同时相加**（如 2 个 + 3 个 = 5 个；克 与 勺 分别列行），按分类排序，可一键复制为纯文本

**AI 推荐（可选，默认关闭逻辑）**
- 结果页「✨ 让 AI 帮我搭一桌」：填 DeepSeek API Key（存 `localStorage`，仅本机）
- 把已选食材 + 候选菜拼成 prompt，请求 `deepseek-chat` 选 3 道并给一句话理由
- 无 Key / 请求失败 / 返回解析失败 → 自动降级为本地规则（缺得最少 + 标签多样性挑 3 道），并提示「已降级为本地推荐」
- 说明：DeepSeek 没有视觉能力，全程只用文本（菜名、食材、标签、时间），不存在「看图识菜」这种假功能

**通用**
- 键盘：`/` 聚焦搜索框，`Esc` 关闭详情/弹窗
- 深色模式：`@media (prefers-color-scheme: dark)` 自动跟随系统，无需手动开关
- 无障碍：主按钮 `aria-*` 齐备，触摸目标 ≥ 44px，`prefers-reduced-motion` 时关闭过渡
- 无横向滚动：390 宽与 1440 宽实测 `scrollWidth === clientWidth`

## 九、已知局限

1. **用量不做「单位换算」**：合并清单只在单位相同时相加（`2 个 + 1 个 = 3 个`），`克` 与 `勺` 会分两行列出，不做密度换算（没有可靠的通用换算表，硬换会算错）。
2. **份量固定 2 人份**：数据里 `servings` 都是 2，暂不支持「按 4 人份翻倍」自动换算用量。
3. **146 种食材暂无对应菜谱**：食材库刻意比菜谱宽（316 vs 用到 170），方便你按真实库存勾选；如果勾到的都是冷门食材，可能一道「现在就能做」都没有——这时结果页会给出「差得最少」的那道菜作为目标。
4. **葱姜蒜算「蔬菜」不算「调料」**：因此缺小葱会算「差 1 样」。这是有意的（很多人冰箱里确实没有葱），想宽松一点可以自己把 `ingredients.js` 里这几项 category 改成「调料」。
5. **菜谱步骤 4–6 步**：为保持可读性，没有把每步拆到更细；复杂硬菜（如松鼠鳜鱼）同样是 6 步概括。
6. **AI 推荐需要联网 + 有效 Key**：离线时按钮仍在，但会直接走本地规则并提示降级。Key 以明文存在 `localStorage`，只适合个人本机使用。
7. **没有 Service Worker**：本来就是 `file://` 双击即用，不注册 SW 反而不受 http 作用域限制；离线能力来自「零外部资源」而不是缓存。
